# Unified food search (approval checkpoint)

**Contract/compatibility.** `GET /v2/foods/search?q=chicken%20breast[&cursor=…]`. Normalize case/whitespace; require 3–120 characters (`zz` → 400, zero upstream calls). Any successful source, including empty, means 200; all active sources failing means 503; client throttling means 429 + `Retry-After`. Errors: `{"error":"Try again"}`. Preserve `/v1` bytes, behavior, caches, and existing tests. Intentional exception (2026-11-07): `/v1` USDA results use the v2 serving basis, rounding, and display text, and their cache keys carry a basis version ([evidence](../evidence/usda-v1-basis/README.md)). Deploy Worker before app.

```json
{"query":"chicken breast","results":[{"id":"usda:123","source":"usda","externalProductID":"usda:123","sourceName":"USDA FoodData Central","sourceURL":"https://fdc.nal.usda.gov/food-details/123","name":"Chicken breast","brand":null,"barcode":null,"servingDescription":"100 g","gramsPerServing":100,"nutrition":{"calories":120,"protein":22,"fat":3,"carbs":0},"requiredReviewNutrients":[]}],"nextCursor":null}
```

**Sources/normalization.** One adapter module + registry entry: `search(query, cursor, deadline) -> {items,nextCursor}`. Run all concurrently under one 8-second abort deadline, initially OFF + USDA. OFF selects restaurant-legacy or Search-a-licious, without retry chains; barcode-like queries use one product lookup. Fetch 12/source; return the entire deduped batch (no discarded overflow). Reuse raw Worker decoders. Worker alone normalizes search nutrition: kcal, grams, sodium/cholesterol mg; OFF serving → grams-scaled 100 g → explicit 100 g basis. USDA Branded nutrients are per 100 g or 100 ml by serving unit (other data types per 100 g); scale to a known gram or ml serving, and set grams only for gram servings. Preserve missing values/review requirements; never infer mass from volume. Swift decodes arbitrary source strings and maps once to `FoodDraftImportedData`. Barcode Swift mapping remains; preimplementation shared fixture/parity assertions cover serving/100 g, missing values, volume, salt/sodium/cholesterol, and ID aliases.

**Merge/cursor.** Rank: exact barcode/name, phrase/prefix, token coverage, completeness, stable ID (source-neutral). Map/Set dedupe by GTIN-14, otherwise normalized name+brand; preserve conflicting GTINs. Keep one whole record, never mix nutrients; O(n log n). Base64url cursor: version, query hash, batch, per-source positions (null = exhausted), emitted identity fingerprints. Validate query/positions/16 KiB limit; cap at ten batches. Skip exhausted sources, retain failed positions, ignore removed sources; additions join fresh queries.

**Cache/load (approved amendment).** Cache per schema/source/normalized-query/position: USDA 24 h, OFF 1 h, successful empty 5 min; never cache failures or merged responses. Cache API is colo-local. Read before quotas: existing global USDA 14/min; isolated v2 OFF global rolling 8/min gate + upstream `Retry-After` cooldown, fail-closed; existing v1 RPC unchanged and v1 OFF outside this gate. Share client 30/min limiter. Denied OFF cache misses are silently skipped, retain their cursor position, and set only a diagnostic response header. App: minimum 3 characters, **700 ms idle debounce, no minimum spacing**, immediate Search/Return submission. Cancel URLSession on every change and guard generation/cancellation. Continuous “chicken breast” typing produces one Worker request; a 1-second pause after “chicken” produces two, at most four upstream calls, zero with warm caches. Measure actual Worker/upstream calls in E2E at 150–300 ms/character; cancellation cannot undo sent calls.

**Approved caveat.** [OFF discourages search-as-you-type](https://openfoodfacts.github.io/openfoodfacts-server/api/#rate-limits). These bounds are not permission/compliance, especially alongside v1 traffic. Owner explicitly approved this settled-query compromise with server-side protection.

**Swift.** One observable session/client shared by Add Food/meal picker via `.task(id:)`; immediate local search stays separate. “On Device” + “Search Results”, cursor “Load more”, errors only retrying “Try again”. Delete `searchUSDA`, provider enum/switches/display names, fallback/page flags, Search Online buttons, duplicate controllers, source-specific copy; retain keyboard submission. Camera: “Search”. Neutral review notes only when needed; hide search-review source labels, retain persisted provenance/legacy IDs/USDA repair.

**Tests first.** Failure modes: source timeout, one 5xx, all fail, USDA budget exhausted, duplicates, empty/short queries, rapid typing/stale ordering (app E2E), page 2 with exhausted source, malformed items, upstream/client 429; additionally cursor tampering, partial/cache behavior, unknown source, normalization parity. Capture failing tests/main-build RED before implementation; prescribed Worker/Swift/iPad validators, deploy/live v2 + v1 probes, then repeatable GREEN typing/retry/camera/AX5 evidence under 5 MB.
