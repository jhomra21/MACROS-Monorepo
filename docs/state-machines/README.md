# MACROS implicit state-machine research

## Confirmed conflicts

**Four source-confirmed defect families, five failed rules. No app code changed.**

1. **F1, deletion retry:** a lost server-deletion acknowledgment leaves no local cleanup journal; retry must authenticate a tombstoned identity. `SharingSyncService.swift:474–485`.
2. **F2, interrupted migration:** a destination base file makes a partial base/WAL copy look complete on relaunch. `SharedModelContainerFactory.swift:67–100`. Conditional on committed data remaining in the source WAL; no observed data loss.
3. **F3, removed person:** authoritative roster removal prunes cache, but detail falls back to the original visible snapshot. `SharingPersonScreen.swift:20–32,220–227`.
4. **F4, invite contract and uncertain replacement:** the final-hour threshold replaces a still-valid link; losing the reply leaves the revoked link cached. `SharingSyncService.swift:366–380`, `sharing.ts:69–84`.

Full repository paths, numbered counterexample-to-source replays, impact limits, proposed reproductions and decisions are in [FINDINGS.md](FINDINGS.md). Immediate food purge on Pro expiry is **one policy question**, not a confirmed unauthorized-read bug. Two deliberately overstrong diagnostics, local/cloud entitlement equality and absence of obsolete widget files, are **dismissed**, not additional defects.

### Counting rules

`P` is the Cartesian product of explicitly listed finite control domains **before** transition constraints. `R` is the reachable distinct state count from the listed initial state. Model counts are exact **for those abstractions only**, not the app. Steps count reachable state/action transitions as reported by statechart, not UI actions or chart arrows. The widget model checks logical selection eligibility at control checkpoints, not physical redraw of an already-displayed timeline or atomicity after the last cross-process check.

Examples: deletion `2×3×2×7 = 84`; migration `2×2×5 = 20`; invites `2×2×2×2×8 = 128`; person `3×2×2×3×2×2×2 = 288`; upload `2×2×2×5×3×3×3×3×2 = 6,480`; purchases `2×2×3×2×3×2 = 144`; scope `2×3×2×2 = 24`; widget `2³×2×2×2×2×4×3×2 = 3,072`.

For unmodeled rows, `R=?≤P` explicitly means **not measured**; only the upper bound is known. Product dimensions describe a documented observation projection: `present/absent` for optional values/tasks/data, `empty/nonempty` for collections, `same/different` for identities, and the named phase alternatives. Full values (UUIDs, tokens, dates, text, counts, paths, queues and models) are data-bearing and usually unbounded for this analysis. A finite control product must not be mistaken for exact cardinality of all source values. Impossible combinations such as buying+restoring or canceled+current must be excluded by transitions, not assumed away because flags happen to correlate today.
